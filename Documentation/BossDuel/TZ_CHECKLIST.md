# Avatar of Nature — чеклист доведения boss-fight до ТЗ

Рабочий документ для последовательной доводки тестового задания «Битва с Боссом».

## Главная цель

Сохранить текущую сильную идею — игрок читает намерение босса и использует его атаки против него — и довести её до понятного двухфазного boss-fight из задания.

Критический пользовательский цикл:

```text
намерение босса
→ телеграф атаки
→ уклонение или заманивание атаки
→ изменение арены
→ открытие слабого места
→ короткое окно для burst-урона
→ переход к следующему этапу
```

## Что сохраняем

- [x] Круговую арену с разрушаемыми секторами.
- [x] Неподвижного босса в центре арены.
- [x] Систему намерений босса (`AvatarBossIntentController`).
- [x] Планировщик атак (`AvatarBossAttackScheduler`).
- [x] Систему телеграфов и визуальных предупреждений.
- [x] `AvatarBossDuelController` и окна уязвимости.
- [x] `AvatarBossWeakPoint`.
- [x] Stagger как реакцию босса и награду за правильное решение.
- [x] Bootstrap-сцену с выбором сложности перед загрузкой боя.
- [x] Текущие временные ассеты и визуальный стиль прототипа.

Примечание: runtime regression использует явно обозначенный test-only hybrid nudge/finisher для детерминированного завершения проверки. Это не часть обычного gameplay-потока и не должно попадать в финальную демонстрацию.

Не добавлять новую механику, пока не доказано, что она улучшает хотя бы один из трёх результатов:

1. игрок понимает намерение босса;
2. игрок понимает, как использовать атаку против босса;
3. успешное решение меняет состояние боя.

Если пункт не помогает ни одному из этих результатов, он не является приоритетом для тестового задания.
